## 5. Proposed `ci.yml` (Step 5)

Triggers on **every** PR and every push to `main` (no path filter, so a Python-only PR still runs the website schema check and vice-versa). Three jobs run in parallel; pip + pnpm caching keeps each ≲ 3 min.

```yaml
name: CI
on:
  pull_request:
  push:
    branches: [main]
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true
jobs:
  python:                       # ruff (advisory) + pytest (excl. smoke)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.9', cache: pip, cache-dependency-path: pyproject.toml }
      - run: pip install -e ".[dev]"
      - name: ruff (advisory — WC paths only; see cp-10.2 notes §6)
        continue-on-error: true        # <-- decision D4
        run: ruff check simulation/ scripts/ ingestion/ models/ utils/ evaluation/ tests/ --output-format=github
      - name: pytest (excluding the smoke job's test)
        run: pytest -q --ignore=tests/scripts/test_snapshot_regen_smoke.py

  python-smoke:                 # the cp-09-class protection
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.9', cache: pip, cache-dependency-path: pyproject.toml }
      - run: pip install -e ".[dev]"
      - name: regenerate-snapshot smoke
        run: pytest -q tests/scripts/test_snapshot_regen_smoke.py

  website:                      # lean, cross-cutting, secret-free
    runs-on: ubuntu-latest
    defaults: { run: { working-directory: website } }
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with: { version: 9 }
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: pnpm, cache-dependency-path: website/pnpm-lock.yaml }
      - run: pnpm install --frozen-lockfile
      - run: pnpm exec tsc --noEmit
      - name: vitest (unit only; integration needs DB secrets — covered by snapshot-deploy.yml)
        run: pnpm exec vitest run tests/unit
```

Plus `pyproject.toml`: add `exclude = ["the-21j-problem/"]` to `[tool.ruff]` (belt-and-suspenders with the explicit-paths invocation). Plus `tests/scripts/test_snapshot_regen_smoke.py` (the smoke test; `tests/scripts/` already exists).

## 6. Design decisions

**D1 — Three jobs (python / python-smoke / website).** Recommend **yes** (parallel; clear failure attribution; required by the merge checklist).

**D2 — ruff `the-21j-problem/` exclusion: pyproject AND workflow.** Recommend **both**. `[tool.ruff] exclude` guards any `ruff check .` (editor/local/other-workflow); explicit WC paths in the yaml make the scope visible. Matches El Voto's explicit ask.

**D3 — Smoke as a pytest test (Option a).** Recommend **yes**: `tests/scripts/test_snapshot_regen_smoke.py`, asserts the script exits 0 **and** that `website/public/data/latest/snapshot_meta.json` was (re)written (more robust than exit-0 alone, per the prompt's decision tree). The `python-smoke` job runs it by path; the `python` job `--ignore`s it (no double-run, no `[tool.pytest]` marker change → no shared-config touch). Locally runnable: `pytest tests/scripts/test_snapshot_regen_smoke.py`.

**D4 — ruff is ADVISORY (`continue-on-error: true`), not blocking. ← needs your decision.** The configured baseline is 669 (pyflakes-only 85), uncleanable here (frozen code + shared `[tool.ruff]`). Blocking would red-light every PR. The cp-09 *class* of bug is a runtime crash caught by the **smoke test**, not by ruff, so advisory ruff does not weaken cp-10.2's stated protection. Recommend advisory now + a named follow-up checkpoint **"lint cleanup & ruff rule-tuning (coordinate `E402`/`N806`/`N803` ignores with El Voto)"**, after which `continue-on-error` flips off and ruff ratchets.
  - *Alt A:* defer ruff from the gate entirely (cleaner, but the PLAN lists ruff).
  - *Alt B:* gate on a curated `--select` after a small targeted fix of the ~4 genuine pyflakes (`F821` undefined-name ×2, `F811` ×2) — but that touches frozen code (out of scope) and the remaining F401/F841 volume still blocks.
  - **Recommend: advisory (D4 as written).**

**D5 — mypy NOT in the gate.** Configured `strict=true` but 264-error baseline; same uncleanable/shared-config problem. Defer per the prompt's out-of-scope ("mypy is a separate quality concern that can land later"). Folds into the same future quality checkpoint as the ruff cleanup.

**D6 — website job = `tsc --noEmit` + `vitest run tests/unit`** (not full `pnpm test`). Full suite's integration tests need DB secrets (fork/El-Voto-unsafe); unit suite is green secret-free and covers the acceptance-critical schema test. `snapshot-deploy.yml` already runs the full secret-bearing suite + build + visual on website PRs — cp-10.2 deliberately does not duplicate that; it adds the lean cross-cutting check that runs on **all** PRs.

**D7 — Do not modify `snapshot-deploy.yml` or add eslint.** `snapshot-deploy.yml` is a shared workflow (touching it ⇒ El Voto coordination) and out of scope. eslint isn't gated today; `tsc` covers type errors; defer.
